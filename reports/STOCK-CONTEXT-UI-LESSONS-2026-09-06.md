## 五项可执行结论

| 优先级 | Ducky 的改法 | 验收方式 |
|---|---|---|
| 1 | 从用户已有的股票想法进入：该股票相关博主内容、公司事件、价格背景，最后设置条件。首页展示这个实际路径。 | 从一只股票进入博主和雷达，股票上下文不丢；不会自动关注或启用通知。 |
| 2 | 首页只展示一张具体的、有日期和来源的股票研究卡。先解释为什么出现，再给事件、技术、期权三个并列维度。 | 日期、来源、缺项可查；“查看证据”为主动作；不添加未经回测的新综合分。 |
| 3 | 用少量可修改的筛选示例降低第一步成本。 | 点击“高管买入 + 超跌”等例子后，进入真正预填的编辑器，能看到 AND/OR 及当前数据日期。 |
| 4 | 博主提及、明确观点和历史结果分开。 | 股票标签能找到内容；未核实内容默认不进入摘要；提及不生成多空判断；回测保留原发表/记录窗口。 |
| 5 | 付费前让用户核对覆盖，先体验一个完整例子。 | 标明最新可用资料和缺项；明确虚构模拟与真实历史；没有完整样本时只展示收录进度。 |

这些是设计判断，不是已经通过转化实验的结论。Prospero 的公开产品页把候选、筛选、学习分别展示，并在首屏用手机产品图和单一下载动作表现用途；可以借鉴层级，不复制品牌、素材或收益话术。[官方产品页](https://www.prospero.ai/app)

Prospero 的评级说明把数字定义为跨股票的相对排序，允许并列。Ducky 不能把别人的 80 分变成 80% 上涨概率；预测市场概率也应独立显示合约定义和报价时刻。[官方评级说明](https://app-support.prospero.ai/how-ratings-work)

其长期信号页明确区分预测期限和不同使用目标；Ducky 应把博主发言的期限、回测观察窗口和下一日历事件分开展示。[官方长期信号说明](https://www.prospero.ai/learn/long-term-signals-overview)

## 本次已补上的股票与博主连接

原博主页只有“我的关注 / 发现”，普通搜索按子串匹配，无法直接以自己的股票找到未关注作者。

- `#/creators?ticker=MU`：按已收录内容中的精确股票标签或带证据的股票观点匹配整个目录。MU 不匹配标题里的 Musk。
- `#/creators?scope=watchlist`：读取已有自选股，在所有已收录博主中筛选相关内容；不是只看已关注博主。
- 同一股票范围传递到观点回测和持仓模拟，来源视频、图表和相关雷达均可点击。
- 默认的已审核摘要限制保留，未核实档案仍须主动展开；匹配股票不生成多空判断。
- 页面写明标签覆盖限制与“提及不代表看多或看空”。一次公开 API 抽查包含 181 篇记录，124 篇带股票标签，但仅 7 篇是已审核摘要，其中 1 篇带股票标签。这是当次返回窗口，不是完整频道覆盖或永久数量。

前端仅增加一次已有自选股的读取，不调用模型，不抓视频，不建立通知。根任务可给股票卡增加 `#/creators?ticker=<TICKER>` 入口。下一阶段应把有来源的实体提及独立于方向观点保存，保留证据位置、审核状态和原始版本；不能用浏览器字符串猜公司身份来补覆盖。
