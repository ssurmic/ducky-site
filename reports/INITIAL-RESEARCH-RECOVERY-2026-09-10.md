## 已确认的代码问题与修复范围

正式中英文切换曾出现整列摘要读取失败，手动 Refresh 后恢复。同期 API 日志200、
浏览器未记录异常不足以定位最初的错误原因，不能认定都是服务器慢或模型排队。

原自动刷新只观察成功的 GET。首个请求失败后，该路径没有自动补读机会。
现在仅 `/me/stock-research` 与 `/stock-research/:ticker` 的首次网络/超时或指定
临时服务器错误可进入已有刷新表，最多两次恢复尝试，沿原轮转/退避调度运行。
成功后恢复正常来源重验；恢复预算耗尽后保留失败状态，用户仍可手动 Refresh。
产品聚焦模式原间隔30秒，每轮一个路径；这不是每个接口30秒完成的 SLA。

隐藏/离线页暂停；离开页面、取消和账户epoch变化停止。401/402/403/429、
会话变化、非研究请求、搜索、历史游标、写入均不会因首次失败被自动重放。
没有额外的按股票请求、行情抓取或模型生成。正常成功后的权限变化/来源撤回
继续通过原服务端及前端校验执行。

原15秒超时在响应头返回时已清理；现在 JSON 响应体读取也受同一个期限约束。
原 `detail=network` 兼容字段保留，增加 timeout/cancelled 分类。raw Response
调用仍由调用者消费 body，不宣称它也获得 JSON 期限。

自选股将 API 读取/数据格式失败与 render 异常分开。后者不会清空已接受的
结果再谎报为后端未生成。内部 console 仅记录阶段、枚举原因、HTTP状态，
不记录响应原文、URL查询、账号或token；无需新增遥测服务。
