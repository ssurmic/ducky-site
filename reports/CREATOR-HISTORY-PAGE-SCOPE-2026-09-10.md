# 作者历史第一页的关注范围 · 2026-09-10

状态：本地实现和测试通过，未发布。来源是正式登录浏览器中真实重现的问题。

用户从左栏 Creators 点 Call history 后看到 “No matches in this batch”，需要再点 Load more。
原因是 Pro/open 模式的 `/kol/research` 默认返回全库第一页，前端再用已关注作者过滤。
“当前这批没有匹配”虽然没有谎称全库为空，但让已存在的历史记录不可见，多加了一步。

## 同数据对照

13:36 UTC 按正式浏览器选择器显示的同一组 10 位作者，只读比较原有 feed 查询：
全库第一页 50 项，筛选后 0 条观点；先限定作者再分页，第一页返回 47 项、包含 22 条调用记录中的观点。
22 是返回 calls 数，尚未经界面去重、分组及状态筛选，不计作 22 条已交付独立观点。
原发表时间与分页游标保留，无模型调用或生产写入。

## 修复

API 增加可选 `following=true`，从已认证账号读取关注关系，与当前可访问作者范围取交集，
再交给原 `kol.research_feed(allowed_creators=...)`。既有 SQL 在分页前限定作者，游标绑定这个范围。
没有新表、采集、价格计算或推理；空关注返回空结果，不偷偷回退全库；Discover 和个别未关注作者仍可正常访问。

前端 Call history 的 Following 视图及后续翻页都传同一标志，保留本地范围复核。Discover 不传这个限制。
关注/权限改变导致旧游标失效时，保留可读当前页并让 Retry 从第一页开始，避免一直重试同一无效游标。
没有自动遍历全库、扩大分页上限、修改关注关系或伪造历史。

此修复使已存在的作者历史更容易找到，不证明作者内容全部收录、收益正确或目前所有日期/语义均已通过人工验收。
