# Ducky：今日研究工作台与证据阅读体验改进计划

## 1. 决策与研究边界

第一阶段不是重做首页、全站换皮、再造投资 OS 或复制 Bobalor。目标是在旧功能旁边添加一个小而完整的、默认关闭的研究入口：用户先看到与自己的关注相关的已有材料，然后直接核对原文，再进入原有详情。

用户要求保留现有免费权益和前后端行为。工程上不能许诺绝对零风险；本方案把这个要求落实成受限改动范围、只读数据适配、隔离样式、默认关闭、回归基线、人工上线闸门和可验证回滚。旧代码不变也可能被共享样式、额外查询或缓存影响，因此验证不能只看 git diff。

证据来自 Bobalor Today / Radar 用户截图、Ducky 两张个股证据截图和本次公开页面核对。没有本地仓库、登录后全流程、数据字典、真实时延或用户行为数据。所有组件名、路由名和配置名在本文中都是建议；只有 G00 确认后才成为项目实际映射。来源见 `05_SOURCES.md`。

## 2. 从竞品学什么，不学什么

Bobalor Today 截图第 1 页先给主要变化，再给重点内容、自选及作者记录；第 2 页接邮件入口。Radar 第 1 页让图、筛选、侧栏和表格相连，后续大量页面展示完整明细。值得学的是“一眼知道先看什么，再逐步深入”的组织方式，不是它的英文标题或报纸配色。[S1][S2]

| 观察 | Ducky 的改进 | 不照搬的部分 |
|---|---|---|
| Today 的分区与重点内容降低找入口的成本 | 做“与你有关的近期材料”，优先已有关注 | 不用总体 ticker 数作为唯一主标题，不把无关全市场热度压在个人内容之前 |
| Radar 总览和明细使用同一组结果 | 用同一数据选择器驱动小型讨论概览与明细 | 先不加气泡图，不用几百行初始 DOM 展示全部历史 |
| 作者/股票/来源可跳转 | 统一新卡片到旧详情与原文的入口 | 不复制他人 UI 代码、字体文件、logo、数据或文案 |
| 全站编辑式层次清楚 | 改进字号层级、段落密度、分隔和留白 | 不全站强制变米白色或改变现有主题偏好 |
| 指标有方法说明 | 显示明确的记录、视频、作者数量及范围 | 不新造 BubbleIndex、胜率、买卖建议或“全网共识” |

Bobalor 方法页把其权重说明为启发式且未按结果校准。因此不把“有综合分数”当成必须追赶的优势。[S4]

用户 Today 截图还可见很长的小数、某些“无近期信号”文案旁同时出现变化值。这里不判定其算法错误；只是提醒新 UI 必须把缺失、范围、分母和格式讲清，不能用强烈视觉替代语义准确性。[S1]

## 3. Ducky 的具体机会

公开页面已出现“首页方案 / A聚焦 / B汇流 / C日报”入口文字，本次无法验收对应交互。G00 必须搜索这些真实字符串，判断它们是已有路由、模板、查询参数、局部试验还是仅一段入口文字。不能看见名字就假定已实现，也不能忽视它们另建第四套系统。[S3]

用户的 AVGO 截图已有股票、作者、观点和原文时间点。它的任务是证据详情，不应与竞品 Today 首页直接比较胜负。下一步是增加从“最近有什么值得查”到“具体证据”的短路径，而不是替换导图。

截图中的仅提及记录可以降低视觉优先级，但必须继续可访问；看多、看空、背景和原始记录数量不因排版被重新定义。新视图不把“未收录看空”写成“没有风险”。

另一张截图的摘录同时有 367、3057 与约 12 倍的表述。没有回听原音频及核验财务出处，不能替换任何数字。将其登记为数据核查问题；本轮保留原文和校正版本，不在适配层静默修正，更不能把“转录校正”自动改成“公司事实已确认”。

## 4. 两个阶段，只有阶段 A 属于当前 Goal

### 阶段 A：默认关闭的只读产品体验

实现预览壳、只读适配器、近期相关资料、统一证据卡/原文入口、范围明确的筛选搜索和可选的轻量讨论概览。所有数据来自已有安全读取路径；页面加载、搜索、滚动不得启动采集、重新摘要、回填或通知。

既有关注/提醒操作只通过原有页面或完整复用已确认的交互路径完成；新页面不自动创建任何订阅。旧功能开关关闭后的页面、接口语义、权限和资源行为不应出现未批准变化。

阶段 A 缩短发现和阅读的时间，不会自动提高视频收录速度，也不会自动获得更多来源。

### 阶段 B：单独批准之后再做

跨全历史服务器检索、保存搜索并持续推送、真正的论点变化检测、首次发现/处理/送达时间埋点、更多平台、公开分享页、作者主页增强。任何涉及新表、新索引、写入、队列或通知语义的实现都属于另一项经批准的工作。

券商 MCP、交易、付费墙、价格/额度调整、模型升级、全站主题重构、抓取策略变更不在本轮。

## 5. 首屏与用户故事

建议名字“今日研究 / Research Brief”，但副标题必须说明筛选日期。若只有旧记录，改称“最近已收录”，不能把旧内容包装成今天刚发布。

桌面首屏建议为：一个标题和范围说明；“我的关注 / 全部已覆盖”切换；股票、作者、日期及文本筛选；最多三项相关的实质记录；清楚可点击的原文与历史入口。下一屏是其他更新和可选的讨论概览。保留“进入原有工作台/全部工具”的明显出口。

示意（所有数量和时间由实际数据决定，不能把示例装进生产）：

    今日研究          当前范围：近 7 天 / 我的关注
    数据覆盖：已收录范围；最后检查时间未知时明确说明
    [股票] [作者] [日期] [在当前结果中查找…]

    先看这些
    AVGO · 某位已覆盖作者 · 来源发布日期
    作者的具体说法；只使用已有摘要，不现场编写投资判断
    [查看原话] [已有历史] [原有个股页面]

    其他记录：仅提及、背景资料可展开
    讨论概览：股票 / 独立视频数 / 作者数 / 记录数 / 最近发布
    [全部工具] 保留原有导航

没有关注名单：显示已覆盖范围和设置入口，不冒称“专属于你”。没有匹配结果：显示条件和清空入口，不自动把无关热门股票伪装成匹配。某来源失败：成功数据继续可读，但覆盖状态标记为部分，不显示“没有新内容”的确定判断。

### 关键故事

故事 A：已有用户查看 AVGO + 某作者的资料，点原文进入正确视频时间点，返回后筛选和滚动状态保留。

故事 B：同一个视频产生数条记录，只计一个视频；全部原始记录仍能展开，且没有修改旧页面的记录计数。

故事 C：用户误把“新增收录”理解成“刚发布”。通过单独标明来源发布日期与收录时间（字段存在时）避免误解；缺失精确时分秒时不得生成“3 分钟前”。

故事 D：新入口关闭或发生错误，旧自选、信息导图、博主、雷达、图表和历史仍然可用。局部失败不能把用户锁在一个空白新首页。

## 6. 组件边界：按真实技术栈适配

以下为逻辑组件名，不要求 React，不是既有文件路径。模板项目用 partial，已有前端框架用其原生组件。

| 逻辑组件 | 输入 | 输出/边界 |
|---|---|---|
| ResearchBriefShell | 已有主题、语言、权限和预览开关 | 只包裹新页面，不能影响旧全局 layout |
| CoverageStatus | 已有时间/成功失败字段 | 成功、部分、未知；不伪造“实时” |
| ResearchFilters | 当前授权数据范围、过滤状态 | 一致筛选，加载范围内搜索必须写明范围 |
| EvidenceCard | 单条只读 view model | 摘要、作者、股票、日期、状态及动作 |
| EvidenceDetailLink/Panel | 已有原文、校正文本、URL、offset | 优先跳原有详情；隔离可重用组件才允许内联，原值不改 |
| ResearchUpdateList | 同一过滤结果 | 稳定排序和可逆折叠，不能重新解释方向 |
| DiscussionOverviewTable（条件项） | 已有 ID 和同范围记录 | 有来源的客观计数，缺字段就省略或标未知 |

优先把完整体验做出来，再抽象。不要为了七个组件增加一个全新状态框架、图表库、向量库或设计系统。

样式继承现有主题，在新根节点内命名空间隔离。已有深浅色都须可读；不改 body、全局 reset、通用 button/table/h1 选择器、既有主题 token 的默认值。建议沿用项目的间距和字号比例，正文避免极小字号；文字/数字区分层次，不用每项都发光和抢眼。移动端改成单列，原文/来源操作不能只靠 hover。

## 7. 数据适配：新增读取视图，不改变事实来源

首选：现有安全查询/服务 → 新模块纯函数适配器 → 新页面。禁止为新页面更改现有 API 的字段类型、分页默认值、方向枚举或修改持久化记录。排序/折叠只作用于新数组，禁止原地修改被旧页面共享的对象或缓存。

首次只复用已确认不会触发写入/生成的读取路径。GET 也不自动代表安全：审计读接口有没有惰性回填、缓存写入副作用或后台任务触发。如果没有安全、有限量的数据路径，记录 BLOCKED，不能为赶进度新建后端聚合接口或绕过鉴权。

### 只读字段能力表

agent 必须把下列逻辑字段逐个映射到真实字段、类型和权限；不存在就写缺失，不许写入假字段。

- 记录 ID、来源文档/视频 ID、作者 ID、规范证券 ID/符号及别名来源。
- 来源 URL、时间点、原始摘录、已存校正摘录、已有摘要。
- 记录类型、作者立场、转录核对/事实核对的具体含义及各自状态。
- 来源发布日期及精度、首次收录时间、处理完成时间、通知送达时间（后几项很可能没有）。
- 可读取的关注名单、当前用户/租户、语言、已授权来源范围。
- 查询窗口、分页游标、是否全部加载、已知部分失败。

sourcePublishedAt、firstSeenAt、processedAt、deliveredAt 是概念字段，不是要求迁移数据库。只有实际存在且含义明确时才展示；updated_at 不得替代所有时间。日期精度只有 day 时，用绝对日期，不构造秒级延迟。只知道“页面生成时间”也不能称“数据已检查到此时”。

### 可逆折叠与排序

相同持久化记录 ID 的完全重复响应可折叠；保留引用和冲突版本。缺少可靠 ID 时，不按相似文字删除记录。同视频不同论点不合并成一条事实；不同作者说法相似，不等于独立事实已经交叉验证。

相关性排序使用可解释规则：当前用户明示过滤/关注、已有记录类型、来源发布日期、稳定 ID。不要让未知立场变成看空/看多，不自创概率或“最有价值”分数。

### 讨论概览的口径

recordCount 是当前范围内去除传输重复后记录数；videoCount 按已存在的稳定视频 ID 去重；creatorCount 按稳定作者 ID 去重。缺少 ID 不能拿标题凑全，显示缺项或不出该指标。最多先展示 20 行及分页/更多入口；下钻与计数使用相同过滤与数据范围。

P0 不显示 bull/bear 比例、预测分数和变化榜。若未来做比例，必须先定义未知/背景的分母、样本量、来源集中度、同一论点的可比条件。不要用“无看空记录”给出绿色安全暗示。

## 8. 搜索与历史的现实边界

若现有后端支持 ticker/creator/date/text 等过滤，在原契约内组合调用；对快速输入使用项目已有的取消/过期响应保护，避免竞态把旧结果覆盖新条件。

若后端没有全文检索，只在已加载的有限结果上查找，并明确标“在当前结果中查找”。不可下载全库到浏览器，也不可把 50 条结果说成“搜索全部历史”。URL 状态须验证、编码并保留已有参数；不加入 token、私人名单或原文全文。

P0 的历史入口只显示已有记录或原有历史页。没有同论点的可比较前后记录，就用“相关历史”，不用“立场反转”。没有 lastViewed/持久化已读状态，就用日期窗口，不用“你上次之后”。

## 9. 隔离、配置、性能

G00 先找现有 feature flag/实验入口；可安全复用则复用。若必须新增，可用一个本模块专属默认 false 开关，名字在审计后确定。示例 `researchBriefV1` 只作说明。开关关时不新增旧页请求、轮询、import 副作用或数据库查询；新路径按现有路由规则返回不可用或旧页链接。开关不是鉴权；服务端原有访问控制始终有效。

优先使用已有查询参数预览/独立受保护路由，不能自动把新页换成根首页或登录默认落点。代码分割依现有能力做，禁用时不让新图表和新样式扩大旧页资源。详情按需加载，禁止每张卡各跑一次完整研究（N+1）或页面刷新就重新生成摘要。

私人筛选不进公共 CDN/共享缓存；缓存必须继承现有鉴权范围，登出/换账户清除用户相关状态。未登录不能通过预览开关、URL 或 SSR 数据绕过原来的授权/公开内容延迟限制。

初始性能保护建议：相同环境至少 5 次对比基线，记录中位数与慢样本；旧路径无新业务请求和模型调用；新页 100 条固定记录不随卡片数产生线性远端查询；旧页面资源或响应时间回退超过 10% 或约定阈值即暂停调查。这是保护阈值，不是已测得性能。

## 10. 任务顺序与完成定义

G00 仓库/配置/权限发现；G01 回归基线；G02 只读适配与语义测试；G03 默认关闭预览壳；G04 完整 Brief 首屏；G05 原文/历史动线；G06 搜索筛选；G07 有数据前提的轻量概览；G08 响应式、键盘与性能；G09 全回归与回滚交付。依赖与停止条件在 `03_TASKS.json`。

工作量只能在审计后估计；已有组件/测试较完整时，可把约 6–10 个有效开发日作为排期假设，不能当成交付保证。先完成从已有一条真实记录到用户原文入口的纵向切片，而不是一次性铺满空组件。

完成是：必需 P0 在隔离环境通过可重现测试，有真实浏览器证据，原路径与数据契约未出现未批准回退，开关默认 false，回滚演练有记录。仅在 fixture 模式可运行不等于真实数据接通；仅 lint/build 通过不等于产品完成；未执行的检查必须列出。

阶段 A 完成后停在人工审查。部署、灰度人群和生产配置仍由用户批准。后续观察是否减少查原文步骤、提高有意义的回访；没有真实用户试验前不声称留存或付费提高。
