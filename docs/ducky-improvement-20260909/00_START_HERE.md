# Ducky 产品改进执行包

这是给本地 coding agent 的实施规格，不是已经应用到 Ducky 的代码补丁。当前交付仅完成公开产品/用户截图审查、实施任务设计和交付包检查；尚未取得真实仓库、运行应用测试或修改生产环境。

## 本轮目标

保留目前免费的产品和全部已有入口，在独立预览入口中，用已有数据交付一个“今日与我有关”的研究工作台。用户能找到相关内容、缩小结果范围、打开原话，并返回原有完整研究功能。学习 Bobalor 的信息组织和阅读层次，不复制其品牌、页面代码、指标或付费墙。

第一阶段改进可读性和可发现性，不改采集/模型/调度来承诺更低发布延迟；真正提高收录速度必须另开后端项目。

## 使用方法

把整个 `ducky-improvement-pack/` 放进真实仓库的 `docs/` 中；若目录已存在，不覆盖它，换一个新目录并相应修改下面的引用。`references/` 是研究资料，不要放进网站 public 目录、打进生产前端包或擅自公开。

在本地 agent 中打开真实项目根目录。首先确认项目原有的 AGENTS.md / CLAUDE.md / 工程规范，再让 agent 读取 `02_AGENT_PROMPT.md`。不要用本包覆盖已有 AGENTS.md、PLANS.md、config.toml 或应用配置。

建议先发：

```text
/plan 读取 docs/ducky-improvement-pack/02_AGENT_PROMPT.md，并只执行任务 G00 与 G01 的仓库发现、安全测试环境检查和回归基线。先映射真实路径、接口与现有 A/B/C 首页方案，再提出最小只读预览实现；此阶段不改生产业务代码。把结果写入包内 execution/，不要只在聊天里总结。
```

检查审计结果后，再发：

```text
/goal 按 docs/ducky-improvement-pack/02_AGENT_PROMPT.md、01_PRODUCT_PLAN.md、03_TASKS.json 和 04_ACCEPTANCE.md 完成全部必需 P0 任务。先确认 G00/G01 已有证据，再逐个实现、测试、浏览器验收并记录。保留免费权益、全部原有功能与数据契约；仅在本地/隔离测试环境工作；新入口默认关闭。不执行迁移、生产写入、采集/模型/通知改造、支付、券商或新平台接入，不推送或部署。缺少关键数据则诚实降级或标记 BLOCKED，不伪造功能；所有必需任务都有验收证据才可称完成。完成后停在待人工发布审查。
```

上述命令适用于客户端实际提供 `/plan`、`/goal` 的 Codex；先看本机命令菜单和版本。其他 agent 直接读取相同文件，按相同状态机执行，不假定存在同名命令。不要为跑任务关闭沙箱、提高全局权限或自动升级工具。当前官方 Codex CLI 文档建议把长规格放在文件，`/goal` 只引用它。[S5]

## 文件分工

| 文件 | 用途 |
|---|---|
| `01_PRODUCT_PLAN.md` | 用户问题、竞品借鉴、范围、组件和数据边界 |
| `02_AGENT_PROMPT.md` | 本地 agent 的完整实施指令 |
| `03_TASKS.json` | 有依赖关系、验收与阻断条件的任务列表；不是可直接运行的脚本 |
| `04_ACCEPTANCE.md` | 不回归、数据真实性、交互、权限、性能及回滚检查 |
| `05_SOURCES.md` | 证据、网址、截图定位与未知项 |
| `templates/REPO_MAP.md` | 仓库发现的填写模板 |
| `references/` | 用户原始资料与选择性页面渲染 |

agent 应新建 `execution/REPO_MAP.md`、`REGRESSION_BASELINE.md`、`EXECPLAN.md` 和 `FINAL_REPORT.md`，并把实际代码路径、命令、结果、证据和阻断事项写进去。生成本执行包时，这些任务均未执行。

## 建议的首个审查问题

agent 能否清楚回答：“关闭新功能开关后，旧页面为什么不会加载新代码、发新请求或多运行模型？”如果还回答不了，先不要让它大规模改 UI。
